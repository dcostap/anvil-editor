# Markdown table editing

## Semantic presentation

Implemented as the first Phase 7 GFM table slice.

Parser-confirmed GFM tables render as compact aligned grids while inactive. SemiBold header and body cells share measured per-column widths and honor delimiter-row left/center/right alignment, source pipes become subtle renderer-drawn outer and per-cell grid borders that do not depend on font glyph coverage, and the delimiter source row becomes the horizontal rule between header and body instead of a padded text row. Cells use neutral backgrounds, proportional horizontal padding, and vertical breathing room rather than accent-colored headers and dense Editor-height stripes. Whole-cell inline code hides its backtick markers, uses the normal code face/background, and remains an unbroken inline-code chip. The grid occupies only its natural measured content width when it fits rather than painting a full-width Editor background. Pipe-shaped text outside a confirmed table remains ordinary Markdown.

Tables may use the full editor viewport even when prose uses a narrower configured wrap column. When the natural grid is still wider than that viewport, flexible columns shrink toward header- and unbreakable-code-aware minimum widths and ordinary cell text wraps internally. Every logical table row remains one source/wrapping row while its visual-row height expands to the tallest wrapped cell. Borders and every following column therefore stay aligned across continuation text instead of allowing the generic Document line wrapper to restart content at the editor margin. Width changes and viewport changes participate in each line's render-cache identity, ensuring every row adopts one table layout instead of mixing stale widths. The compact delimiter source row is too short to contain gutter text, so its line number is intentionally suppressed instead of overlapping the following row's number.

Cell fragments retain explicit displayed-text source bounds after whitespace trimming and inline-code marker removal, including a valid zero-width position for empty cells. Every internal wrapped text line also retains its own source range and two-dimensional cell bounds, so pointer resolution, caret geometry, selection painting, and navigation use both the cell's horizontal position and the clicked continuation row. Multiline fragments paint and advance by their assigned column width rather than their unwrapped source width, keeping every later border fixed. Focusing a cell reveals only that cell's inline Markdown source while the row and delimiter remain in the grid. Edits touching a resident table invalidate that complete table's layout while unrelated edits leave its measured layout cached.

Edits synchronously rebuild an optimistic source-mapped table row while semantic parsing catches up, avoiding a temporary raw-row flash. Width changes invalidate and remeasure the complete semantic table. Escaped pipes and matched backtick runs do not split cells. Inconsistent, oversized, malformed/incomplete tables, parser uncertainty, and capture overflow remain raw.

Interactive Table Editing keeps the source-mapped grid active while cells are edited. Dragging within one cell selects an ordinary text range; crossing a cell boundary upgrades the drag to a rectangular group of complete cell contents represented as ordinary multiple selections. Complete cell selections have a distinct cell outline, including cells whose selected contents are empty. Active cells reveal their inline Markdown source without revealing their containing source rows. The grid retains optimistic rendered rows through ordinary text input, deletion, paste, and IME composition instead of flashing raw source while semantic parsing catches up, and optimistic rows remeasure with the viewport. Inactive and active cell presentations reserve compatible geometry so cursor movement does not resize ordinary table rows. Every row draws its border and cell fragments at the shared grid's explicit column coordinates; source mappings position carets within those cells but never reposition the grid itself. Wide rendered tables retain their meaningful minimum column widths and extend the Document View's ordinary horizontal scroll range instead of clipping unreachable columns; this overflow scrollbar remains visibly expanded, and the shared scroll transform keeps editing geometry aligned. Cell input preserves existing pipe escapes, escapes only structural pipes, converts source newlines to `<br>`, and leaves pipes and `<br>` literal inside code spans. Matching multi-cursor and primary-selection paste payloads pass through the same normalization. Hover Insertion Controls on canonical header-column and first-cell row boundaries scale with editor zoom, use compact circular hit targets without generic square overlays, and fade in progressively as the pointer approaches their zones; they insert at the indicated edge, while every structural operation remains available through commands. Tab and Shift+Tab select the next or previous cell, Enter selects the cell below and appends a body row when necessary—including at end of Document—and Shift+Enter inserts a canonical `<br>` visual line break. Home, End, and vertical navigation use each cell's own wrapped visual lines. `<br>`, `<br/>`, and `<br />` are presented as cell-local line breaks and navigated or deleted atomically. Source Mode, fenced code, mixed/cross-cell selections, and tables outside presentation limits retain ordinary editing behavior instead of routing Interactive Table Editing commands.

The grid remains a projection of the authoritative Markdown Document rather than a second editable data model. Text input escapes cell pipes, pasted newlines become `<br>`, and all edits use ordinary multi-selection Document transactions. The following palette commands edit canonical leading/trailing-pipe tables:

- `markdown-live-preview:table-insert-row-above` / `table-insert-row-below`
- `markdown-live-preview:table-delete-row`
- `markdown-live-preview:table-move-row-up` / `table-move-row-down`
- `markdown-live-preview:table-insert-column-left` / `table-insert-column-right`
- `markdown-live-preview:table-delete-column`
- `markdown-live-preview:table-move-column-left` / `table-move-column-right`

Row commands preserve existing row text and never delete/move the header or delimiter row. Column commands preserve exact cell interiors, including alignment-marker text, and apply one undoable multi-line transaction. The command context must come from a current semantic table and every affected row must have consistent canonical outer pipes. Optional-pipe, malformed, incomplete, inconsistent, or stale structures are declined instead of normalized or partially rewritten. Pipe discovery ignores escaped pipes and matched backtick runs.

Focused UI coverage verifies aligned header/body cells, padded neutral presentation, internal multi-line cell drawing with one source wrapping row, stable active/inactive row geometry, compact delimiter and bounded backgrounds, active-cell identity refresh, visible partial selections, empty and non-empty full-cell outlines, same-cell text drag, cross-cell rectangular Table Cell Selection, Hover Insertion Controls, whole-table and optimistic viewport width remeasurement, wide-table horizontal overflow and scrolled hit testing, multi-selection navigation and paste, cell-local Home/End/vertical movement and selection collapse, lexical pipe/`<br>` behavior, IME-safe optimistic rendering, EOF-safe Tab and explicit row insertion, Source Mode/fence/fallback/mixed-selection routing, deletion/movement, and undo restoration.
